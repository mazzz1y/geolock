# GeoLock v1 config schema (legacy)

Shipped through GeoLock 1.4.x. Configs marked `version: 1` are migrated to v2 automatically on extension start and on import. v1 is no longer accepted by the validator and cannot be saved directly.

## Top-level shape

```json
{
  "version": 1,
  "default_action": "allow",
  "data_sources": {
    "geoip":   { "url": "", "auto_update": true, "interval_hours": 24, "sha256_url": "" },
    "geosite": { "url": "", "auto_update": true, "interval_hours": 24, "sha256_url": "" }
  },
  "dns": {
    "cache_ttl_seconds": 300,
    "negative_cache_ttl_seconds": 30,
    "timeout_ms": 1500,
    "match_strategy": "first"
  },
  "rules": []
}
```

## Rule shape

```json
{
  "name": "",
  "enabled": true,
  "action": "block",
  "strip_referrer_on_navigation": false,
  "bidirectional": false,
  "website":  { "kind": "any" },
  "resource": { "kind": "any" }
}
```

| Field | Type | Notes |
|---|---|---|
| `name` | string | Display label. |
| `enabled` | boolean | Disabled rules are skipped at evaluation. |
| `action` | `"allow"` \| `"block"` | Outcome when the rule fires. |
| `strip_referrer_on_navigation` | boolean | When `action: "block"`, strips the Referer header on top-level navigation instead of cancelling. |
| `bidirectional` | boolean | When true, the rule fires whether the page-resource pair appears in the rule order or its reverse. |
| `website` | matcher | Matches the page making the request. |
| `resource` | matcher | Matches what the page is loading (the request target). |

## Matcher shape

Every matcher has a `kind` discriminator.

| `kind` | Body fields | Meaning |
|---|---|---|
| `any` | — | Always matches. |
| `geosite` | `tag` (string), `attr` (string, optional) | Matches a v2fly geosite category, optionally scoped to an attribute. |
| `geoip` | `tag` (string) | Matches the resolved IP country. |
| `domain` | `regex` (string) | Matches the hostname against a regex. |
| `url` | `regex` (string) | Matches the full URL against a regex. |
| `ip` | `cidr` (string) | Matches the resolved IP against a CIDR. |
| `all_of` | `terms` (array of matchers) | Logical AND. |
| `any_of` | `terms` (array of matchers) | Logical OR. |
| `not` | `term` (matcher) | Logical NOT. |

## Migration to v2

The migrator (`worker/config/migrations.js`) transforms a v1 config into v2 by applying these renames:

| Location | v1 | v2 |
|---|---|---|
| Rule field | `website` | `source` |
| Rule field | `resource` | `destination` |
| Rule field | `strip_referrer_on_navigation` | `strip_referrer` |
| Matcher discriminator | `kind` | `type` |
| Matcher type | `all_of` | `and` |
| Matcher type | `any_of` | `or` |
| Matcher body (and/or) | `terms` | `matches` |
| Matcher body (not) | `term` | `match` |

Migration runs recursively through composite matcher trees. When both legacy and modern keys coexist on a rule or matcher, the modern key wins.

Configs without `version: 1` are not migrated. v2 configs containing v1 names are invalid and rejected by the validator.
